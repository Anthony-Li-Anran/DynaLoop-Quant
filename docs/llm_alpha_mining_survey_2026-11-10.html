一手证据支持的结论

1. 在「预测市场」这一层，LLM 基本是冗余的。价量数据是低语义数值序列；正式综述报告里 GPT-4o、DeepSeek-V3、Qwen3-32B 表现基本持平；RLVR 的 spurious-reward 实验显示，用与正确答案无关甚至错误的奖励训练，数学任务仍能大幅提升，说明 RLVR 更多是能力激发而非知识注入。起作用的是搜索结构、受限文法与可验证反馈，不是模型里的金融世界知识。

2. 赛道工程成熟，但样本外优势缺乏统一证据。FactorBench 在统一协议下回测约 5,000 个 AI 挖掘因子、跨 5 个市场：没有任何范式稳定胜出；中性化后多数方法的残差 IC 归零或翻负；多空收益远低于多头收益，说明多头利润主要是市场 beta；2016 年手写的 Alpha101 在各层级仍具竞争力。

3. 「怎么教」的成熟答案是可验证奖励，不是金融知识灌输。模型输出受限 DSL 表达式 → 编译执行 → 在固定窗口上算 IC/RankIC 或回测指标 → 该数值直接作为 reward，不经过 LLM 自评或人类偏好。GRPO 用组内相对优势、无需 critic，适合稀疏标量奖励。

4. 金融的「可验证」与数学/代码不是同一种可验证。金融奖励可计算但内禀嘈杂，r = r* + ξ 且噪声方差远大于信号；按 n₉₅ = ⌈(1.96σ/α)²⌉，判定一个 modest edge 需要数千笔样本（约数百交易日），而数学题 n₉₅ = 1。直接用 P&L 当 verifier 会退化为 reward hacking。

判断（非定论，供讨论）

项目已确认的定位是「不是用 AI 做量化，是用量化做 AI 研究」：量化是考场，研究对象是自主科研模型如何避免自进化偏差——模型在自己产出的有偏反馈上加速自欺。因此 LLM 在预测层冗余恰是这个考场的优点：反馈是数值的、可复现的、不依赖 LLM 自评，才能把「模型学会了」与「模型在骗自己」分开。现有框架里 LLM 兼任 evaluator（QuantAgent 的 judge、AlphaAgent 的语义对齐检查）正是自评，属于要被卡掉的虚假反馈来源。

Anthony 在 2026-11-10 提出：统计与不确定性怎么定义，可能要等模型做出来再决定。本次调研支持这一判断——文献里至少存在三种互不等价的「保证对象」：单个因子的显著性、整个发现过程的任意停时错误控制、以及策略-奖励耦合造成的自我确认偏差。选哪一个取决于研究循环怎么构造，先定统计口径等于预设研究对象。

02领域现状：从「能生成」走向「可验证」

2.1 范式演进

东方证券（2026-06，C）把 LLM 驱动因子挖掘划为七阶段；Agentic Quantitative Trading 综述（arXiv:2608.31041，B）则把 agentic 因子挖掘归为四类机制：生成式、协作式、自演进式、工具增强式。两者可拼成一条主线：

前置
理论因子 → 公式化 Alpha → 传统自动搜索
CAPM / Fama-French；Alpha101/158 等可回测表达式；遗传规划与 RL 批量扩展。此时没有 LLM。
2023–2024
LLM 直接生成 + 交互助手
Alpha-GPT 把研究者的自然语言思路翻译成可执行因子；一次性生成或带用户反馈回路。FITEE 综述称其为 miner / interactive assistant。
2024–2025
知识增强与 Agent 闭环
R&D-Agent / R&D-Agent-Quant（NeurIPS 2025）以 Qlib 为回测底座，假设→代码→回测→反馈五步循环；FAMA、QuantAgent、AlphaAgent 引入记忆、writer-judge 循环、原创性与复杂度约束。
2025–2026
自演进 + 工具增强 + 参数级内化
CogAlpha（ACL 2026）代码级演化与多 agent 质检；QuantEvolver 把反馈从 prompt 搬进模型参数；AlphaPilot 用 GRPO 训练多轮工具调用；Hubble 等用领域算子语言与 AST 沙箱。
2026 前沿
评估治理：从「能生成」到「可验证」
Propose, Don't Judge 提出把判决权交给 agent 不可触碰的冻结统计裁判；FactorBench 用统一协议给出系统性负面结论。

2.4 不能回避的负面证据

负面结果（应与方法论文并置阅读）

FactorBench（arXiv:2610.06947，B，本轮经第三方摘要转述）：统一协议回测约 5,000 个 AI 挖掘因子、5 个市场。没有任何范式稳定胜出；训练 IC 到验证期大幅蒸发；中性化后 R&D-Agent 复合 IC 从 0.0253 降至残差 0.0011，GP / AlphaGen / AlphaForge / AlphaSAGE / AlphaAgent 残差 IC 翻负；多头 CAGR 22.4%–31.2%，多空仅 0.3%–6.5%；Alpha101 每一层级都保持竞争力。作者自列局限：静态股票池有幸存者偏差、残差 IC 只控五类暴露、成本与借券假设简化。

独立复现（SAIL Lab，C）：CSI300 / 2022 样本外，QuantaAlpha 无进化 −0.78%、有进化 −1.13%，而 20 个经典量价因子 Alpha158 基线 +13.69%。单一年份单次实验，不宜外推为判决，但足以说明「论文结论 ≠ 可复现结论」。

290 因子案例（RD-AGENT 系列社区复盘，C）：多场实战共 290 个因子，自报超额最高 +26.5%，独立验证零存活；一个 +18% 的 carry 策略复核后发现是展期日重复扣减复权的口径 bug，修正后 +3.18%、t=0.66 不显著。注意：该数字来自社区实战复盘而非同行评审论文，此前在项目笔记里被当作赛道痛点引用，本报告将其降级为案例。

03「LLM 对金融市场是冗余的」——分层核实

Anthony 于 2026-11-10 提出此质疑。以下按「预测层」与「研究主体层」分开核实，不把质疑解读成放弃 LLM 或放弃项目。

3.1 预测层：证据支持「冗余」

证据内容级别
模型规模无差异Chain-of-Alpha 在 GPT-4o / DeepSeek-V3 / Qwen3-32B 上表现大致相当（FITEE 综述汇总）；CogAlpha 自述符号/公式方法常产出「冗余或缺乏经济依据」的表达式A
RLVR 是能力激发用与正确答案无关甚至错误的奖励在 Qwen2.5-Math-7B 上做 RLVR，MATH-500 仍提升 13.8–24.1 分（真值奖励 29.1 分）；在 Llama 3 / OLMo 2 上基本失效。收益的一部分与奖励正确性无关B
文法比知识重要QuantEvolver 用 14B 小模型 + 受限 Factor DSL + 参数更新超过大模型 prompt 循环；放开 DSL 后性能崩塌B
数据边界决定「品味」社区复盘：真正有产业逻辑的因子集中在人类预先放入面板的特色数据（基差、持仓量）；没有这些列，假设空间退化为纯价量。LLM 做的是「给定材料空间内的高效搜索」C
统一基准下无优势FactorBench：中性化后多数方法残差 IC 归零或翻负，LLM 因子池比非 LLM 搜索更接近已公开的 Alpha101 公式B
小结

价量是低语义数值序列，语言先验里没有未来收益。若目标是「用 LLM 预测市场 / 挖到能赚钱的因子」，LLM 确实冗余，甚至会因流畅的伪逻辑解释而更有害。起作用的是搜索结构、受限文法与可验证反馈，不是世界知识。

3.2 研究主体层：冗余性反而构成考场优势

项目内部已确认口径（AGENTS.md §1.1、PROJECT.md、2026-11-10 项目日志，D）：方向是 QUANT 与 AI 的交叉，学术意义优先于 PnL，研究 + 工程双修；本质不是「用 AI 做量化」而是「用量化做 AI 研究」，量化是考场，研究对象是自进化偏差；标语为「统计保证的 Wake-Sleep 自进化量化研究闭环」。

在这个定位下，LLM 不是市场预测器，而是研究主体：提出假设、写表达式、读取反馈、修正。市场提供的是硬反馈——数值、可复现、不依赖评判者的自然语言意见。正因 LLM 无法靠语言先验「读懂」市场，反馈里才不会混入世界知识，才能把「模型真的学会了」与「模型在自己骗自己」分开。

与项目立论的关系（判断）

FITEE 综述里的 LLM as evaluator 正是「自己评自己」；ICML 2026《Breaking the Self-Confirming Loop》把它形式化为：模型过度奖励高置信度错误，形成 self-confirming loop。这类自产反馈恰好是项目所谓「自进化偏差」的可度量对象。因此「冗余」质疑不推翻项目，反而帮它把研究对象钉得更准。

04「要怎么教模型去做这件事」

4.1 教什么：不是金融知识，是「产出可执行假设并接受外部裁决」

成熟的训练形态是 RLVR / 可验证奖励：模型输出受限 DSL 表达式 → 编译器/Realizer 变成可执行代码 → 在固定数据窗口上算 IC / RankIC / 回测指标 → 该数值直接作 reward，不经过 LLM 裁判或人类偏好打分。冷启动（SFT / 种子因子库）只用来学 DSL 语法与合法输出格式，不用来学市场。

GRPO（DeepSeekMath 2024 提出）去掉 PPO 的 critic：对同一 prompt 采样一组 G 个响应，用组内均值与标准差构造相对优势

Aᵢ = (rᵢ − mean(r₁…r_G)) / (std(r₁…r_G) + ε)

再以 PPO 式裁剪目标加对参考模型的 KL 惩罚更新。奖励为 0/1 二值时，组内优势直观等价于「同伴里有几个也做对了」；实践中省一份 critic 显存。IBM Research（arXiv:2503.06639，B）证明该归一化可化约为加权对比损失，具有「成功放大」性质。

4.2 三条已知失效路径

失效机制与项目的关联
组内奖励全同全对或全错时优势为零，该组无梯度（DAPO 动态采样丢弃此类组）稀疏奖励下训练信号本身就稀缺
长度 / 难度偏置Dr. GRPO 指出按长度归一化会拉长错误输出；除以组内标准差在「几乎人人答对」时放大优势因子表达式长度与复杂度需单独控制
验证器不完备通过可见测试 ≠ 正确；策略可能钻评分器或格式漏洞，典型 reward hacking「评估」与「真相」不是一回事
Mode collapseQuantEvolver 报告：无多样性奖励时，模型反复把 lookback 5 改成 6 刷同一模板候选集合退化会让统计校正的分母失真

4.3 金融场景为何不能直接照搬

Trade-R1（arXiv:2601.03948，B）给出最清晰的诊断：金融奖励可验证但内禀嘈杂，r = r* + ξ 且 Var(ξ) ≫ r*；于是「正确决策亏钱、错误推理赚钱」成为常态，标准 RL 会退化为动量机器，为历史赢家编造理由（hallucinated rationales）。该工作不以 P&L 直接作奖励，而引入过程级三角一致性（证据↔推理、推理↔决策、证据↔决策）作噪声过滤器，等于承认 P&L 不是合格的 verifier。

噪声地板的量级

95% 置信判定一个真实 edge 所需样本 n₉₅ = ⌈(1.96σ/α)²⌉。以日波动 3.46%、单笔 edge 0.1% 计约需 4,598 笔样本（日 20 笔 ≈ 230 天）；数学/代码任务 n₉₅ = 1。这与 §5.2 的「≈500 交易日认证等待」是同一统计事实的两种表述。

4.4 因子侧最接近的工作（含一处必须澄清的措辞）

  • QuantEvolver（arXiv:2605.15412）：种子因子 → 跨时间窗任务库 → Factor DSL → Regime Backtest → DiCo（diversity-complementarity）奖励 → Mined Factor Database。它把历史反馈从 prompt 搬进参数，避免 context explosion 与 feedback drift。B
  • AlphaPilot（arXiv:2610.15488）：明确使用 GRPO，训练多轮工具调用；评估器返回 IC / RankIC / 稳定性或执行错误；终端奖励基于未来窗口的因子池表现，而非每条轨迹做完整组合回测。B
  • CogAlpha（ACL 2026）：代码级因子表示；多 agent 质检含语法修复、经济合理性判断、以及检测时间泄漏的单测。A
措辞澄清（修正此前对话中的说法）

此前对话里把 QuantEvolver 描述为「GRPO + 受限 DSL」。核对其 arXiv 摘要后应更正：该文自述为 Reinforcement Fine-Tuning（RFT），摘要未明说使用 GRPO；只是「组内相对奖励 + 可执行评估 + 参数内化」在结构上接近 GRPO/RLVR 思路。明确使用 GRPO 的是 AlphaPilot。综合调研亦指出：未检索到以「GRPO + 可验证奖励 + 统计控制」为框架、并公布统计控制的正式发表合流工作。

4.5 与本项目现有接口的客观差距

此节只陈述代码事实（D），不提改造方案：

  • strategies.py 的策略是代码对象（BaseStrategy 生命周期），配置只选类与 kwargs；因子是表达式 / 数值序列，两者形态不同。
  • BacktestResult.metrics 只有 total_return / max_drawdown / turnover / bar_count / fill_count / rejected_count / final_positions / reconciliation_max_abs / annualized_volatility / sharpe_ratio 等策略绩效指标；src/ 全库检索无 GRPO、reward、factor DSL、IC / RankIC 的实现。
  • 因此「评估」这一环虽已成型，口径是策略回测绩效，不是因子有效性。

05统计可信度：整条链条最薄弱处

本节直接回应 Anthony 的口径「统计与不确定性怎么定义，可能要等模型做出来再决定」：文献里已经存在数种互不等价的「保证对象」。

5.1 Agent 循环同时违反三个经典假设

Propose, Don't Judge（arXiv:2609.27051，B）指出，现有 agentic 系统让同一个 agent 提议、回测、筛选、退役全包，而它们使用的 t 统计量、IR、甚至 deflated Sharpe 都假设检验批在事前固定：

Agent 行为被破坏的假设
读到判决再改，直到通过可选停止（fixed-sample 检验失效）
把幸运因子的近似重复一起提交多重检验（批量校正假设检验数固定）
学习评估器奖励什么验证器在环适应
在评估期上训练知识截断泄漏

事前计算的多重检验校正需要「事前已知的提议过程」，而学习型 agent 没有这样的过程。因此固定批量校正在数学上不适用，只能靠 anytime-valid（序贯）推断。

5.2 已有的一类解法：冻结裁判 + 任意停时有效

该文构造：裁判只读提交后揭示的市场结果；对每日 rank-IC 流下注，W_t = ∏(1 + λ_s X_s)，λ 在结果揭晓前确定并封顶，构成 test supermartingale / e-process（Ville 不等式保证任意停时有效）；自相关必须白化，否则 AR(1) ρ=0.2 会把 5% 名义水平放大到约 6% 误纳；入库用 online e-BH 控 FDR，退役用 e-detector。

对「统计保证」定义问题的含义

这里「统计保证」保证的不是某个因子显著，而是整个自我演进过程在任意停时下的错误发现率。它与「裁判必须稳定，进化的只是运动员」这一项目既有表述高度同构，但它是文献中的一种具体解法，不等于项目已选定它。

5.3 另一类对象：自奖励导致的自我确认偏差

《Breaking the Self-Confirming Loop》（ICML 2026 / arXiv:2510.08977，A）研究 self-rewarding RL（RLIR）：reward 与策略置信度强耦合，模型对高置信度错误过度奖励，形成自确认循环，偏差随训练累积并向 over-reward 漂移。文中给出三个度量：

  • ρ_noise — 奖励估计偏差的绝对幅度（相对 oracle reward）
  • ρ_selfbias — 策略-奖励耦合强度，即环路对偏差的放大程度
  • ρ_symbias — 过度奖励 / 奖励不足的不对称偏斜

其缓解方案 RLER 用多模型集成奖励与 disagreement-aware 采样降低耦合。另有 MIT CSAIL 的 RLCR（经二手报道，C）指出标准 RLVR 会让模型的置信校准变差，需在奖励中加校准项（Brier score）。这两条线索把「自进化偏差」从口号变成了可度量的量。

一个直接推论

一次 agent session 测试 10⁴ 个候选时，E[max Z] ≈ √(2 ln 10⁴) ≈ 4.29：即便零真实 edge，最优者的 t 统计量也期望达到 4.29。未披露试验数的 t 或 IC 几乎不可解释；所有经典校正都要求「你试了多少次」这个分母。

5.5 三种候选「保证对象」——为什么不急着定

编号保证对象典型工具依赖的模型/循环形态
(a)单个候选因子的显著性IC / RankIC、t 检验、DSR、多重检验校正候选是固定批量、试验数可披露

三者不是「选一个工具」，而是三种不同的研究对象。若先按 (a) 把统计模块做成传统因子显著性工具箱，就把研究对象预设成了固定批量筛选；而项目的研究对象若是 (b) 或 (c)，模型/循环必须先存在才谈得上度量。这与 Anthony 的判断一致，也是本报告不给出统计模块设计的原因。
